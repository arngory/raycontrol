# app-update-v1: обновления Niko через ноду

Статус: **черновик** (2026-11-07; ответы клиента — в §1–§4: semver тега, клиент выбирает сам, нода держит всё из `SHA256SUMS`). Формат — по черновику клиента (#58); владелец одобрил, на ноде **по умолчанию
выключено**. Сервер — raycontrol v0.18.0; клиент — Niko после 1.38.

Зачем: в сети, где GitHub недоступен или медленный, клиент без VPN не может скачать новую версию, а когда GitHub
недоступен совсем — и узнать о ней. Нода видна ему всегда (подписка), а GitHub ей доступен. Она держит у себя
последний проверенный релиз Niko и отдаёт его своим устройствам. Доверие не меняется: клиент проверяет подпись
minisign своим ключом, как для GitHub; нода — только ещё один источник тех же файлов, а версию называет GitHub (§4).

## 1. Подписка

В payload (subscription-v1 §3) — поле `app`:

```json
"app": {"niko": [{"tag": "v1.38.0", "prerelease": false}, {"tag": "v1.39.0-rc1", "prerelease": true}]}
```

- Только релизы, которые нода держит целиком (§3): `SHA256SUMS`, `SHA256SUMS.minisig` и все файлы из `SHA256SUMS`.
- Не больше двух: последний стабильный и последний pre-release, если он новее стабильного (semver тега:
  `v1.39.0-rc1` новее `v1.38.0`, `v1.38.0-rc1` — нет). Стабильный — первым.
- Поля нет: зеркало выключено, ещё ничего не скачано или нода старше v0.18.0.
- Отдаётся всем активным устройствам: в файлах нет ничего, чего нет на GitHub. Подпись подписки поле покрывает; доверие
  к файлам — от minisign клиента (§3).
- Ставить ли pre-release — решает клиент по своей настройке; нода только перечисляет.

## 2. Файлы

`GET` (и `HEAD`) `/app/v1/niko/<tag>/<name>` на порту подписки.

- Тот же TLS с пином, SPA v2, `Authorization: RC1 …` и `X-Raycontrol-Device`, что у `/sub/v1` (subscription-v1 §2).
  Без авторизации, при выключенном зеркале, на тег не из `app` и на имя не из `SHA256SUMS` — **404**, как у подписки.
  Редиректов нет.
- `<name>` — `SHA256SUMS`, `SHA256SUMS.minisig` или имя из `SHA256SUMS` (только `[A-Za-z0-9._-]`).
- `200` целиком или `206` на один диапазон (`Range: bytes=a-b`, `bytes=a-`, `bytes=-n`); на неисполнимый — `416` с
  `Content-Range: bytes */<размер>`. `Content-Length` всегда. `ETag` — SHA-256 файла в hex, в кавычках: годится в
  `If-Range` при докачке (сменился релиз — придёт файл целиком).
- Одна загрузка на устройство сразу и не больше 16 на ноду; сверх — **429** с `Retry-After` (секунды). Клиент ждёт и
  повторяет, начатое докачивает.
- Скорость не ограничена: канал делит TCP. Загрузка, которая 60 с не забирает ни байта, обрывается; медленная, но
  живая — нет.
- **Relay:** relay-v1 пересылает порт подписки на уровне L4 и пути не смотрит, так что `/app/v1` через relay работает
  как `/sub/v1`.

## 3. Нода

- Включение: `rayctl app-mirror on|off`, состояние — `rayctl app-mirror` (что держит, когда проверяла, последняя
  ошибка). `on` требует хотя бы 1 ГиБ свободного места в `/var/lib/raycontrol`. Выключение удаляет скачанное.
- Сразу после включения и затем раз в ~6 ч (со случайным сдвигом до 30 мин) rayd своей сетью спрашивает
  `api.github.com/repos/arngory/niko/releases` без токена (репозиторий публичный) и выбирает последний стабильный и
  последний pre-release новее его (§1). Черновики пропускаются, теги — только semver `vX.Y.Z[-…]`.
- Для каждого выбранного релиза, которого у неё ещё нет:
  1. скачивает `SHA256SUMS` (до 64 КиБ) и `SHA256SUMS.minisig` (до 4 КиБ) из ассетов релиза;
  2. проверяет подпись ключом `RWSNTdeZ59LS1bdwyf4iRzgIdSmDfFWw9yWiy6Qy/eAfBNj5gLnEwmRl` (D5D2D2E799D74D8D,
     `niko-update.pub` клиента; закреплён в raycontrol) и trusted comment — ровно `niko <tag>`;
  3. каждое имя из `SHA256SUMS` — ассет того же релиза, не больше 200 МиБ, вместе не больше 600 МиБ; скачивает и
     сверяет SHA-256;
  4. собирает релиз во временном каталоге и только целым переносит на место.
- Не удалось (сеть, подпись, хэш, размер) — остаётся прежний проверенный релиз того же вида; ошибка видна в
  `rayctl app-mirror`. Релизы, которых больше нет в выборке, удаляются после того, как новый набор собран.
- Файлы лежат в `/var/lib/raycontrol/app/niko/<tag>/` (rayd, 0600): не больше двух релизов, ~110 МБ каждый.

## 4. Клиент

Сторона клиента (Niko, уточнено клиентом 2026-11-07):
- **Версию называет GitHub.** Нода — только источник файлов того же тега. `app` ноды учитывается, лишь когда GitHub
  недоступен никаким путём. Иначе нода, злонамеренная или просто отстающая, могла бы назвать несуществующую версию
  (клиент предлагал бы её на каждой проверке) или держать старую (новый релиз с GitHub не был бы виден).
- Порядок:
  1. о новой версии спрашивает GitHub: через ядро; при выключенном VPN — напрямую, затем через выбранный профиль во
     временном ядре;
  2. если нода держит тот же тег, файлы качаются с неё: напрямую, потом через её relay; с докачкой (`Range: bytes=N-`,
     `If-Range` по `ETag`), на 429 ждёт `Retry-After` (не больше 60 с, 3 попытки), на 200 вместо 206 начинает заново;
  3. не вышло с ноды (404, подпись, нет ответа) — файлы с GitHub тем путём, каким прошла проверка; пара «нода + тег»
     до перезапуска приложения больше не предлагается;
  4. GitHub недоступен никаким путём — предлагается новейший релиз из `app` ноды; подпись проверяется при установке.
- Подпись, trusted comment и SHA-256 проверяются тем же кодом, что для GitHub.
- Выбор стабильного или pre-release — клиента: «Проверить стабильную» смотрит `prerelease: false`, «Проверить
  предварительную» — `prerelease: true`; предлагается только версия строго новее установленной.

## 5. Interop

Для CI клиента — источник релизов и ключ теста. Задаются переменными окружения rayd, только на тестовой ноде:
- `RAYCONTROL_UNSAFE_APP_MIRROR_API=http://127.0.0.1:PORT` — вместо `https://api.github.com`. Нода спрашивает
  `<API>/repos/arngory/niko/releases` и ждёт JSON как у GitHub: `tag_name`, `draft`, `prerelease`,
  `assets[].name`, `assets[].size`, `assets[].browser_download_url`. С ней ассеты можно отдавать и по `http`.
- `RAYCONTROL_UNSAFE_APP_MIRROR_KEY=RW…` — открытый ключ minisign теста вместо ключа Niko.

rayd пишет о каждой в журнал на `WARN` при старте. На рабочей ноде их быть не должно: всё, что подписано таким ключом,
уйдёт её устройствам. `rayctl app-mirror on` проверяет источник сразу, повторное `on` — снова сразу.

## 6. Версии

- raycontrol v0.18.0: зеркало, `app` в подписке, `/app/v1`. Старая нода поля не шлёт, на `/app/v1` отвечает 404.
- Niko после 1.38: читает `app`, качает с ноды.
