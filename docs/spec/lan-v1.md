# lan-v1: локальная сеть устройств пользователя через Yggdrasil

Статус: **черновик, ответы клиента учтены** (2026-11-08). Идея одобрена владельцем, предложение — от клиента Niko. Сервер — raycontrol
v0.23.0 и niko-server v0.16.0 (номера предварительные: v0.22.0 и v0.15.0 заняты
[traffic-limit-v1](traffic-limit-v1.md)), плюс коммит форка yggdrasil-go. Клиент — Niko. Как всё новое, выключено
по умолчанию.

Зачем: устройства одного пользователя видят друг друга по адресам Yggdrasil — через ноду или напрямую в одной Wi-Fi.
Без NAT и IP forwarding, со сквозным шифрованием. С v0.20.1 каждое устройство — свой узел mesh со своим ключом
(`internal/render/yggdrasil.go:52-65`), seed приходит в `niko-ygg` (`internal/sub/sub.go:485`).

Пути без префикса — в этом репозитории. `niko:` — niko-server v0.14.0, `ygg:` — форк yggdrasil-go `0db15d4`,
`iw:` — ironwood `0712ecc`, `sb:` — форк sing-box `34eaa8c`. «Вывод» — не проверено запуском.

## 1. Подписка

### 1.1 Кто попадает в список

Нужны оба согласия:
- **администратора:** `rayctl user lan NAME on|off`, по умолчанию `off`. У пользователя должен быть сервис Yggdrasil;
- **устройства:** заголовок `X-Raycontrol-LAN: on|off` в `GET /sub/v1` ([subscription-v1](subscription-v1.md) §2).
  Нода хранит последнее значение и пишет только при смене. Нет заголовка — ничего не меняется: старый клиент в
  список не попадает никогда.

Почему заголовок, а не вызов API и не флаг при регистрации:
- устройства `user` порт API не открывают ([api-v1](api-v1.md) §5), у устройств из `device add` нет сертификата;
- выбор за тем, у кого устройство, и он меняется; а флаг потребовал бы заново регистрировать старые устройства;
- защищён, как `X-Raycontrol-Device`: TLS с пином и `X25519MLKEM768` (MAC RC1 его не покрывает). Минус — GET с
  побочным действием; зато состояние сходится на каждом запросе.

**Симметрия.** Пароль и список получает только устройство, которое показало себя. Кто не виден, тот не видит:
украденное устройство без согласия о соседях ничего не узнаёт.

### 1.2 Поле `lan`

Необязательное поле payload:

```json
"lan": {
  "v": 1, "svc": 7, "relay": 20, "label": "ams",
  "password": "<base64url, 32 байта>",
  "next": {"password": "<…>", "from": 1767268800},
  "devices": [
    {"id": "<16 hex>", "name": "work.laptop", "label": "work-laptop", "addr": "201:…",
     "next": {"addr": "203:…", "from": 1767268800}}
  ]
}
```

| Поле | Смысл |
|---|---|
| `v` | версия формата `lan`; неизвестную клиент пропускает целиком |
| `svc` | сервис Yggdrasil, через ядро которого идёт сеть; профиль с этим `svc` должен быть поднят |
| `label` | метка DNS ноды по правилам §1.3 из её имени (`name` пакета); без имени — `n-<node_id[:8]>` |
| `relay` | потолок связи устройство—устройство через ноду, Мбит/с на пользователя (§4.4); `0` — только напрямую в Wi-Fi |
| `password` | пароль multicast (§3); только если устройство показало себя |
| `next` | следующий пароль, переход в `from` (вместе с UUID, R4-1) |
| `devices` | показавшие себя неотозванные устройства пользователя, включая это (себя клиент находит по `device_id` из пакета); порядок — по `id` |
| `devices[].id` | ID устройства, как в `X-Raycontrol-Device`; не меняется при ротации и переименовании |
| `devices[].name` | имя из `rayctl device add/invite` (`internal/store/entities.go:31-36`), для показа |
| `devices[].label` | метка DNS устройства по правилам §1.3 из `name`; считает нода, чтобы имена у всех клиентов и версий совпадали |
| `devices[].addr` | адрес текущего ключа: `YggdrasilAddress(YggdrasilDeviceKey(UUID, ключ SPA))` (`internal/render/yggdrasil.go:58-65`, `:82-105`) |
| `devices[].next` | адрес следующего ключа с `from`, как у `profiles[].next` |

В `lan` нет: имени пользователя, ключа пользователя (`YggdrasilKey`: экспорт, старые подписки), отозванных и
непоказавшихся устройств, приглашений, чужих. Нет `lan` — не разрешено, нет сервиса Yggdrasil или нода старше.
`lan` без `password` и `devices` — разрешено, но это устройство себя не показало.

**Версии.** Подписка остаётся v1: новое необязательное поле, как `probe`, `dnsauth`, `app` (subscription-v1 §3).
Внутри `lan.v = 1` — только новые необязательные поля. Старая нода заголовок не читает.

### 1.3 Метки DNS

Имя устройства в сети — `<label устройства>.<label ноды>.niko.internal` (`.internal` ICANN оставила для частного
использования и не делегирует: утёкший запрос ничего не найдёт). Метки считает нода, одинаково для всех клиентов:
1. Строчные буквы (Unicode lower).
2. Кириллица — транслитерацией ICAO 9303: а a, б b, в v, г g, ґ g, д d, е e, є ie, ё e, ж zh, з z, и i, і i, ї i,
   й i, к k, л l, м m, н n, о o, п p, р r, с s, т t, у u, ў u, ф f, х kh, ц ts, ч ch, ш sh, щ shch, ъ ie, ы y,
   ь — ничего, э e, ю iu, я ia («ноутбук» → `noutbuk`).
3. Остаются `[a-z0-9]`, всё прочее (другие письменности, пробелы, знаки, `.`, `_`) → `-`.
4. Повторы `-` схлопнуть, `-` по краям убрать. Двух `-` подряд не бывает, поэтому нет и `xn--`.
5. Обрезать до 58 символов и снова убрать `-` с конца.
6. Пусто — `d-<id[:8]>` у устройства, `n-<node_id[:8]>` у ноды.
7. Метка занята устройством этого пользователя, добавленным раньше, — плюс `-<id[:4]>` (не больше 63). Всё ещё
   занята — `d-<id>`.

Совпадение меток двух нод на одном устройстве клиент разводит сам: суффикс `-<node_id[:4]>` у ноды с большим
`node_id`.

## 2. Изоляция на ноде

### 2.1 Что умеет ядро (по коду)

**Отказать в транзите между двумя своими пирами ядро не умеет:**
- Пересылает ironwood, а не yggdrasil-go: `handleTraffic` отдаёт кадр пиру, которого выбрал `_lookup`, кадр себе —
  слою сессий (`iw:network/router.go:603-616`). Хука нет, фильтра в опциях нет (`iw:network/config.go:10-20`).
- `SetPathNotify` (`ygg:src/core/core.go:216-227`) только сообщает, что путь к ключу найден.
- `AllowedPublicKey` решает лишь, кто станет пиром, и только для входящих нелокальных линков
  (`ygg:src/core/link.go:669-683`); multicast его обходит (`ListenLocal`, `ygg:src/core/api.go:163`).
- `GroupPassword` пускает сквозные сессии только с тем же паролем (`ygg:src/core/core.go:100-105`,
  `iw:encrypted/crypto.go:155-163`). Он один на ядро, а нода говорит со всеми: пароль на пользователя невозможен.
- `PeerFilter` — по IP и только при подключении пира.

**Но фильтр снаружи ядра возможен.** Ключи источника и назначения открыты в каждом кадре traffic
(`iw:network/traffic.go:37-47`), pathNotify и pathBroken (`iw:network/pathfinder.go:448-453`, `:514-519`). Кадр —
длина uvarint и байт типа (`iw:network/peers.go:250-268`, `iw:network/wire.go:7-18`).

**Сейчас все клиенты всех пользователей ноды — одна сеть:** нода пересылает между любыми двумя. Защищает только
фильтр входящих в клиенте (со слов клиента).

**Утечка уже сейчас.** Ядро отвечает на удалённые getSelf, getPeers и getTree любому, у кого есть с ним сессия
(`ygg:src/core/core.go:185-191`, `ygg:src/core/proto.go:78-96`). getPeers отдаёт ключи всех пиров (`proto.go:169-181`).
Любой клиент узнаёт адреса всех подключённых устройств, а с публичными пирами — любой узел общей сети.
`NodeInfoPrivacy` (`niko:nikoserver/yggdrasil.go:114`) этого не закрывает.

### 2.2 Решение: фильтр на линке в niko-server

Каждый линк клиента проходит через niko-server: тот проверяет ключ и копирует байты в ядро
(`niko:nikoserver/yggdrasil.go:351-386`). Вместо `io.Copy` — чтение по кадрам, после `meta` в каждую сторону.

В users-файле у ключа появляется группа: `"yggdrasil": {"public_key": "…", "lan": "u5"}`. Её получают ключи
показавших себя устройств пользователей с `lan=on`, для всех трёх UUID ротации. N — ключ ноды, K — ключ линка, G(x) —
группа ключа (∅ — нет).

Кадры traffic (9), pathNotify (7), pathBroken (8):
- **от клиента** (K → ядро): `source = K` или G(source) = G(K) ≠ ∅; и `dest = N` или G(dest) = G(K) ≠ ∅;
- **к клиенту** (ядро → K): `source = N` или G(source) = G(K) ≠ ∅; и `dest = K` или G(dest) = G(K) ≠ ∅;
- pathBroken несёт `source` и `dest` исходного трафика, но идёт обратно к `source` (`iw:network/pathfinder.go:228-236`):
  для него в правилах выше `source` и `dest` меняются ролями;
- остальное — молча отбросить, счётчик +1. Прочие типы (keepalive, дерево, bloom, lookup) проходят: без них нет
  дерева. Соседей они не выдают: пиру уходят анонсы только своей цепочки предков и его
  (`iw:network/router.go:332-389`), а не всех узлов.

Что это даёт:
- Между устройствами разных пользователей нет ни данных, ни сессий (рукопожатие идёт кадром traffic), ни ответов о
  присутствии (pathNotify).
- Устройство без LAN говорит только с нодой — на деле так и сейчас. Выход в `inner` не меняется.
- Чужие не используют устройство пользователя как транзит через ноду.
- Подделка `source` не проходит: клиент не выдаст себя ни за ноду, ни за чужое устройство.

**Плюс форк yggdrasil-go:** опция `DebugPrivacy` — не отвечать на удалённые getSelf, getPeers, getTree
(`ygg:src/core/proto.go:78-96`). niko-server её включает. Без неё фильтр не поможет: запрос идёт к N, а к N можно.

### 2.3 Публичные пиры (R4-18)

- Их линки набирает само ядро (`niko:nikoserver/yggdrasil.go:116-118`), мимо niko-server. Фильтр стоит только на
  линках клиентов, и этого достаточно: любой кадр к клиенту или от него пересекает его линк.
- **Сейчас** с публичными пирами (вывод по коду): устройства достижимы из общей сети через ноду; нода отвечает
  getPeers кому угодно; нода может быть транзитом между своими публичными пирами.
- **После** первые два закрыты. Третье остаётся: это цена R4-18, а не LAN (§7).
- Клиент на запасном пути (`niko-ygg-via`) сидит в общей сети своим линком. Его защищает только свой фильтр (§5).
  Его трафик к соседям через ноду идёт: `source` в группе.

### 2.4 Отвергнуто

- **Только фильтр в клиенте:** нода — бесплатный ретранслятор между любыми устройствами; чужим — сессии, присутствие.
- **Хук в маршрутизаторе:** пересылка в ironwood (`iw:network/router.go:603`) — нужен второй форк, кода, который
  апстрим активно чинит (в 0.5.15 — несколько правок маршрутизации). Возможно позже, как опция апстрима.
- **Ядро на пользователя:** N адресов и выходов у ноды, N деревьев, память.

### 2.5 Цена

- niko-server: разбор кадра (uvarint, два пути, два ключа), правила, счётчики, fuzz-тест — оценка 200–300 строк.
  Буфер кадра до 128 КиБ (`ygg:src/core/core.go:103`) — из пула.
- Привязка к проводу ironwood протокола 0.5, типы 7–9. Новый формат — новая минорная версия, её ядро и так отвергнет
  (`ygg:src/core/version.go:173`). Обновление форка и тест niko-server идут вместе.
- CPU: на кадр — uvarint и два поиска в map, против расшифровки TLS. Мало (вывод, не замерено).
- Поведение меняется для всех: клиент к клиенту через ноду больше не ходит, даже без LAN. Вывод: этим никто не
  пользуется, endpoint в профиле — detour только для VLESS к выходу ([niko-ygg-note](../handoff/niko-ygg-note.md) §1).

## 3. Пароль multicast

- **На пользователя:** base64url(HMAC-SHA256(`lan_key`, `"raycontrol-lan-v1 password\x00"` ‖ UUID `inner`)).
  `lan_key` — 32 случайных байта пользователя в базе, новый при `user lan on` и при каждом отзыве его устройства.
  43 символа при пределе yggdrasil-go 64 байта (`ygg:src/core/link.go:200-205`).
- **Ротация — с UUID** (R4-1, 30 дней): пароль следующего UUID — в `lan.next` с тем же `from`, в `from` переходят
  все. На интерфейсе действует один пароль, первая подходящая запись (`ygg:src/multicast/multicast.go:205-232`):
  перекрытия нет. Устройство со старой подпиской до обновления отрезано от соседей в Wi-Fi и идёт через ноду.
- **При отзыве** новый `lan_key` меняет оба пароля сразу, без `next`.
- **Только случайный, 256 бит.** Пароль от пользователя не годится (§3.1).

### 3.1 Что видит атакующий в той же Wi-Fi без пароля

- **Что устройство работает с Yggdrasil.** Маяк — UDP на `[ff02::114]:9001` (`multicast.go:71`) каждые 1–15 с
  (`:347`, `:366-367`), формат постоянный (`ygg:src/multicast/advertisement.go:9-15`). В чужой сети (работа,
  общежитие) это признак средства обхода. Поэтому multicast выключен по умолчанию и только в доверенных сетях.
- **Ключ и адрес устройства** — в маяке открыто, живут до ротации UUID (до 30 дней): устройство узнаётся в разных
  Wi-Fi.
- **Какие устройства одного человека:** между их адресами идут линки TLS.
- **Порт слушателя TLS.** Кто завершит TLS, получит сертификат с CN = ключ (`sb:protocol/yggdrasil/endpoint.go:190`).
- **`Hash` маяка** — BLAKE2b-512 открытого ключа с паролем как ключом (`multicast.go:214-230`). По нему пароль можно
  перебирать офлайн, отсюда 256 бит. То же с подписью рукопожатия (`ygg:src/core/version.go:80-92`).

Не может: стать пиром (неверный пароль — отказ, `version.go:157-167`), читать трафик (TLS и сессии ironwood),
узнать имена (по проводу они не ходят, §5), пройти через устройство к ноде. С паролем (украденное или отозванное
устройство до обновления) он становится пиром, и его останавливает только фильтр клиента по списку (§4.2).

## 4. Безопасность и приватность

### 4.1 Что устройство узнаёт о соседях

- У показавших себя: `id`, `name`, `label`, адреса (текущий и следующий), есть ли они в сети; в той же Wi-Fi — ещё
  локальный адрес.
- Не узнаёт: настоящий IP через ноду (нода пересылает), других пользователей и непоказавшихся, ключи (из адреса ключ
  не выводится).
- Подделать адрес соседа нельзя: ipv6rwc отбрасывает пакет, если источник не от ключа сессии
  (`ygg:src/ipv6rwc/ipv6rwc.go:265-275`). Вывод: если клиент идёт через ipv6rwc.
- **Шифрование классическое.** Устройство—устройство защищают сессии ironwood (R1-3). Линк до ноды — TLS с
  `X25519MLKEM768`, но нода видит шифротекст ironwood. В Wi-Fi — `tls://` на crypto/tls, Go ≥ 1.24 предлагает
  `X25519MLKEM768` по умолчанию (вывод). Для важного — SSH или TLS поверх.

### 4.2 Отозванные устройства

- **Нода:** ключ уходит из users-файла, линки закрываются сразу (`niko:nikoserver/yggdrasil.go:235-250`), группы нет —
  фильтр отбрасывает его кадры к соседям. Так же при `user disable` и истечении.
- **Соседи:** устройство пропадает из `devices`, пароль меняется — со следующим запросом подписки. До этого в той же
  Wi-Fi отозванное устройство станет пиром и пройдёт по старому списку на открытые порты. Окно — интервал
  обновления. Предложение клиенту: с LAN обновлять подписку не реже раза в 6 ч и при входе в Wi-Fi; на `404` —
  выключать LAN.
- **У отозванного остаются** старые адреса соседей (до ротации) и старый пароль. Новые он не выведет: ключи соседей —
  от их ключей SPA (`internal/render/yggdrasil.go:58-65`).

### 4.3 Журналы — жёсткое правило

- **niko-server:** фильтр ничего не пишет о кадрах ни на каком уровне, отладку тоже: ни ключей, ни адресов, ни групп.
  Только счётчики: отброшенные кадры (всего) и байты пересылки по пользователю в сокет статистики (§4.4).
- **Имён устройств у niko-server нет:** в users-файле `u<id>-<id устройства>` и группа `u<id>`
  (`internal/render/yggdrasil.go:130-138`).
- **Адрес пира в строках ядра** («Connected inbound …», `ygg:src/core/link.go:694`) — только на debug, как сейчас
  (`niko:nikoserver/yggdrasil.go:542-556`); это пир, не назначение.
- **rayd** смену заголовка не пишет: это активность ([09-observability](../09-observability.md) §1 п. 3); состояние —
  в `rayctl device list`. `rayctl user lan` — в аудите, как действие администратора.

### 4.4 Злоупотребления и пределы

- Пересылка через ноду идёт мимо `inner`, Xray её не считает ([traffic-limit-v1](traffic-limit-v1.md) §1). Без
  пределов LAN — бесплатный VPN между устройствами: домашнее устройство становится выходом для устройства в сети с
  цензурой.
- **Потолок `relay`:** ведро токенов в niko-server на пользователя, на кадры сосед↔сосед (ни `source`, ни `dest` не
  N). По умолчанию 20 Мбит/с (предложение), запас 1 с; сверх — кадр отбрасывается, TCP внутри сбавит темп.
  `rayctl service set ygg lan_relay=<Мбит/с>`; `0` — через ноду нельзя.
- **Байты:** длина кадра, один раз на кадр, по пользователю; в лимит — через `traffic` (traffic-limit-v1 §2.2),
  когда он будет. Прямой трафик в Wi-Fi ноде ничего не стоит и не считается.
- Частая смена заголовка: запись и перерисовка не чаще раза в минуту на устройство (предложение).
- Lookup нода пересылает как раньше; повторы ironwood тормозит сам (`pathThrottle` 1 с, `iw:network/config.go:34`).

## 5. Клиент (кратко, решает клиент)

- **Переключатель** «показывать это устройство» → заголовок в каждом запросе подписки, новый запрос сразу.
- **Endpoint `yggdrasil`:** тот же ключ и пиры, плюс multicast (`MulticastInterfaces`: Wi-Fi, Beacon и Listen,
  Port 0, Password = `lan.password`, смена в `next.from`). Только в доверенных Wi-Fi и не вместе с `niko-ygg-via`:
  иначе клиент — транзит из общей сети к соседям. В форке sing-box такой опции пока нет (`sb:option/yggdrasil.go`).
- **Входящие** — только с `addr` и `next.addr` других устройств из `devices` (и с прежнего `addr` 2 дня после
  `from`), только на открытые пользователем порты, на 127.0.0.1. Остальное — отбросить.
- `DebugPrivacy` (когда будет в форке) и `NodeInfoPrivacy` включены.
- **Имена:** клиент сам отвечает AAAA на `<label устройства>.<lan.label>.niko.internal` по списку (§1.3) и не
  отправляет такие запросы наружу. Имени пользователя в подписке нет: список и так одного пользователя.
- `relay: 0` — к соседу только в той же Wi-Fi. `404` или пропажа `lan` → LAN выключить, список стереть.

## 7. Решения и вопросы

Владелец одобрил идею. Решения по черновику (сервер):
1. **Пересылка через ноду** по умолчанию — 20 Мбит/с на пользователя, в лимит трафика. `lan_relay=0` — только в
   одной Wi-Fi.
2. **Согласие устройства** — заголовок в `GET /sub/v1`, не отдельный `POST`: состояние сходится на каждом запросе.
3. **Маяк** выдаёт ключ устройства до ротации UUID (до 30 дней). Для v1 принимаем: multicast — только в Wi-Fi, которые
   пользователь сам отметил доверенными. Отдельный ключ LAN с короткой ротацией — позже, если понадобится.
4. **Транзит между публичными пирами** через ноду (цена R4-18) — не в этом выпуске. Это отдельная задача: нужен хук
   на линках, которые ядро набирает само.
5. **Окно отзыва** — интервал обновления у клиента: с LAN не реже раза в 6 ч, при входе в Wi-Fi и сразу на `404`.
   Короткий `expires` не вводим.
6. **Симметрия** остаётся: соседей видит только тот, кто показал себя.

Ответы клиента (2026-11-08):
1. Выхода в общую сеть Yggdrasil через ноду не нужно ни одной функции Niko: профиль `niko-ygg` — только detour для
   VLESS к адресу ноды, `200::/7` через него не идёт, входящие на нём отвергаются; «Yggdrasil (эксперимент)» в
   настройках — отдельный узел со своими пирами, нодой не бывает. Фильтр (§2) можно выпускать и раньше LAN. Он же
   отбросит кадры, когда дерево выберет телефон с `niko-ygg-via` транзитом между нодой и общей сетью.
2. Зона — `.niko.internal`; метку ноды считает нода (`lan.label`, §1.3).
3. Формат `lan` подходит. Правила меток — §1.3 с уточнениями клиента (только LDH, ICAO 9303 для кириллицы, без
   `xn--`, суффикс в пределах 63).
