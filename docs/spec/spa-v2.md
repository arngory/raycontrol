# raycontrol SPA v2

Статус: **заморожен** (R0); §10 (TCP-носитель) и поля `node_keys`, `sub` добавлены в R1 без изменения формата пакета. Изменение формата = новая версия (`Version` в пакете и префикс пакета регистрации).
Эталонная реализация — [`internal/spa`](../../internal/spa); тестовые векторы —
[`internal/spa/testdata/vectors.json`](../../internal/spa/testdata/vectors.json). Векторы проверены второй,
независимой реализацией (Python + libsodium).

Все порты ноды закрыты. Клиент отправляет один UDP-пакет на порт SPA текущего слота; если пакет подлинный,
адрес отправителя получает доступ к разрешённым портам на время TTL. Сервер никогда не отвечает на SPA-пакеты.

## 1. Параметры ноды

Выбираются случайно при установке (`rayd init`) и не меняются. Клиент получает их в пакете регистрации (§6).

| Поле | Тип | Диапазон при установке | Смысл |
|---|---|---|---|
| `node_id` | 16 байт | случайные | идентификатор ноды, соль HKDF, часть AAD |
| `epoch_len_s` | целое, секунды | 6–24 ч, кратно минуте | период смены ключа устройства |
| `slot_len_s` | целое, секунды | 5–30 мин, кратно минуте | период смены порта |
| `port_key` | 32 байта | случайные | ключ расписания портов (общий для всех устройств ноды) |
| `port_base` | uint16 | 20000 … 60999 − range | начало диапазона портов SPA |
| `port_range` | uint16 | 1024–4096 | размер диапазона |
| `len_min`, `len_max` | целые | `len_min` ∈ [85, 160], `len_max` = `len_min` + [32, 128], ≤ 512 | допустимая длина пакета |

## 2. Время, эпоха, слот

`t` — unix-время в секундах (UTC).

```
epoch = floor(t / epoch_len_s)
slot  = floor(t / slot_len_s)
```

## 3. Порт

```
port(slot) = port_base + (BE64(HMAC-SHA256(port_key, "raycontrol-spa-v2 port" ‖ BE64(slot))[0:8]) mod port_range)
```

`BE64` — 8 байт big-endian. Сервер держит открытыми порты слотов `slot−1`, `slot`, `slot+1`.
Клиент шлёт на порт **текущего** слота по своим часам.

## 4. Ключ эпохи

У каждого устройства мастер-ключ `device_key` (32 байта, выдаётся при регистрации).

```
epoch_key = HKDF-SHA256(ikm = device_key, salt = node_id, info = "raycontrol-spa-v2 key" ‖ BE64(epoch), L = 32)
```

HKDF — RFC 5869 (extract + expand).

## 5. Пакет

Один UDP-датаграм длиной `L`, где `len_min ≤ L ≤ len_max`; клиент выбирает `L` случайно и равномерно.

```
packet     = nonce ‖ ciphertext
nonce      = 24 случайных байта
ciphertext = XChaCha20-Poly1305-Seal(key = epoch_key, nonce, plaintext, aad = "raycontrol-spa-v2" ‖ node_id)
```

`plaintext` длиной `L − 24 − 16`:

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 1 | версия = `0x02` |
| 1 | 8 | время отправки, unix-секунды, BE |
| 9 | 2 | запрошенный TTL в секундах, BE; 0 = значение сервера по умолчанию |
| 11 | 1 | флаги, должны быть 0 |
| 12 | 1 | `n` — число сервисов в scope, 0–16; 0 = все разрешённые устройству |
| 13 | 2·n | ID сервисов, uint16 BE |
| 13 + 2·n | остаток | нули (padding; после шифрования неотличим от случайного) |

Эпоха, по которой выбран `epoch_key`, должна совпадать с эпохой поля «время».
Весь пакет неотличим от случайных байтов: постоянных полей и фиксированной длины нет.

## 6. Проверка на сервере

1. Пакет пришёл на один из открытых портов SPA; длина в `[len_min, len_max]`. Ограничение частоты на адрес-источник
   выполняется до криптографии (в nftables).
2. Если `nonce` уже принят и не истёк — отбросить.
3. Для эпох `e`, `e−1`, `e+1` (по часам сервера) и каждого активного устройства — попытка `Open`. Первая удачная
   определяет устройство.
4. Версия `0x02`, флаги 0, `n ≤ 16`, scope помещается в plaintext; эпоха времени пакета совпадает с эпохой ключа.
5. `|now − время| ≤ 30 с`.
6. Запомнить `nonce` на 60 с. Если кэш полон и в нём нет истёкших записей — отказать (а не вытеснять).
7. Scope = запрошенные ∩ разрешённые устройству (пустой запрос = все разрешённые). Пусто — отказать.
8. TTL = запрошенный или значение по умолчанию (10 мин), не больше максимума ноды (1 ч).
9. Добавить адрес-источник (IPv4 или IPv6, после NAT) в allow-наборы портов из scope на TTL. Ответ не отправлять.

Устройство активно, если оно не отозвано, его пользователь включён и не истёк, а сервис включён.

## 7. Поведение клиента

- Перед подключением, если действующего доступа нет: отправить SPA, выждать 150–400 мс (случайно), подключаться.
- Продлевать доступ до истечения TTL независимо от моментов подключения, со случайным смещением, чтобы связка
  «SPA → сразу соединение» не была постоянной.
- После смены сети (Wi-Fi ↔ мобильная) — новый SPA сразу: адрес изменился.
- При неудачном подключении — один повтор SPA (порт мог смениться на границе слота); если и он не помог —
  TCP-носитель (§10).
- Часы: допустимое расхождение ±30 с; при большем клиент должен сообщить пользователю о неверном времени.

## 8. Пакет регистрации устройства

`rayctl device add USER NAME` печатает строку один раз:

```
rcdev1:<base64url без '=' от JSON>
```

```json
{
  "v": 1,
  "host": "203.0.113.7",
  "spa": {
    "node_id": "<32 hex>", "epoch_len_s": 34380, "slot_len_s": 1620,
    "port_key": "<64 hex>", "port_base": 21907, "port_range": 2955,
    "len_min": 136, "len_max": 206
  },
  "device_id": "<16 hex>",
  "device_key": "<64 hex>",
  "services": [{"id": 1, "kind": "reality", "name": "reality"}, {"id": 2, "kind": "dnstt", "name": "dns"}]
}
```

Необязательное поле `sub` — эндпоинт подписки ([`subscription-v1.md`](subscription-v1.md)):
`{"port": <tcp>, "pin": "<base64url SHA-256 SPKI>"}`.

Необязательное поле `node_keys` — публичные ключи ноды для проверки подписи подписки:
`{"ed25519": "<64 hex>", "mldsa65": "<base64url>"}`. Клиент, который его не знает, игнорирует поле;
остальные поля и версия `v` не меняются.

Строка содержит секрет устройства: передаётся только по доверенному каналу (QR с экрана администратора, личная передача).
В R3 регистрация переходит в API (одноразовая ссылка, канал с `X25519MLKEM768`), формат полей сохраняется.

## 9. Безопасность

- Симметричные ключи 256 бит: устойчивость к квантовому перебору на уровне 128 бит.
- Утечка `epoch_key` раскрывает только одну эпоху одного устройства; утечка `port_key` раскрывает расписание портов,
  но не позволяет создать подлинный пакет.
- Перехватчик на пути может переслать пойманный пакет со своего адреса раньше клиента. Он получит только сетевой
  доступ; сервисы за SPA требуют собственных учётных данных.
- Попытка расшифровки перебирает устройства × 3 эпохи; при ограничении частоты на источник это дёшево до сотен устройств.

## 10. TCP-носитель

Для сетей, где неизвестный UDP режется целиком, тот же пакет можно доставить по TCP.

- Порт — тот же `port(slot)` (§3); сервер принимает TCP на портах слотов `slot−1`, `slot`, `slot+1`, если носитель
  включён на ноде.
- Клиент открывает TCP-соединение, пишет пакет SPA v2 без изменений (§5) первыми данными и закрывает соединение.
  Запись можно резать на любые сегменты. Ответа нет: сервер читает до EOF (не больше `len_max + 1` байт, не дольше 3 с)
  и сбрасывает соединение (RST).
- Проверка — §6, длина пакета — число прочитанных байт. Кэш nonce общий для UDP и TCP.
- Ограничение частоты SYN на адрес-источник — в nftables, как для UDP.
- Порядок в клиенте: сначала UDP; если подключение после UDP-пакета и его повтора не удалось — один раз TCP-носитель
  и снова подключение. Запоминать для сети, какой носитель сработал.
- Цена: пока слот активен, его порт отвечает на SYN и виден сканеру как открытый. Порт меняется каждый слот
  и ничего не отдаёт.
