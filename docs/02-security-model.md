# 02. Модель безопасности

Статус: **принята** (редакция 2, по решениям из [08-decisions.md](08-decisions.md)).

## Угрозы

| Противник | Что делает | Чем закрываемся |
|---|---|---|
| Массовые сканеры | Ищут открытые порты и сервисы. | Все порты закрыты (policy drop); ответа нет ни на что, кроме своих DNS-зон на UDP 53. |
| DPI и активное зондирование | Классифицирует трафик; повторяет соединения клиента со своих адресов. | Без SPA порт молчит; за SPA — протоколы, устойчивые к зондированию (REALITY self-steal, naive без `407`, masquerade). |
| **Разработчик правил DPI** | Изучает публичный код проекта и строит сигнатуру, которая блокирует **все** установки сразу. | Нет постоянных байтов, длин, портов и таймингов: случайные параметры каждой установки + ротация ключей, порта SPA, учётных данных, REALITY и SNI. |
| Квантовый противник «запиши сейчас — расшифруй потом» | Сохраняет трафик, чтобы расшифровать позже. | Постквант обязателен везде, где протокол его поддерживает; остальное — через `inner` с ML-KEM-768. |
| Пользователь прокси | Пытается достать локальные сервисы, метаданные облака, API ноды. | Запрет приватных и служебных сетей в маршрутизации и в nftables по UID процесса. |
| Взломанный процесс ноды | Пытается достать ключи других сервисов или управлять файрволом. | Фронт и бэкенды — разные процессы и пользователи; у фронта нет ключей пользователей; `CAP_NET_ADMIN` только у `rayspa`. |
| Сторонняя платформа | Видит метаданные, блокирует аккаунт, меняет API. | Сквозное шифрование через `inner`; выделенные аккаунты или аккаунты пользователей; резервные аккаунты. |
| Соседи по CGNAT | Получают сетевой доступ вместе с клиентом, у которого общий с ними IP. | Доступ после SPA — только сетевой; дальше обязательна аутентификация в сервисе. |

Вне модели: root на хосте, консоль хостера.

## Эшелоны

```
пакет из интернета
  ├─ 0. nftables, policy drop. Для всех открыт только UDP 53 (свои DNS-зоны) и TCP 443 на время ACME.
  ├─ 1. SPA v2: один пакет на ротируемый порт → адрес клиента получает доступ к разрешённым портам на TTL.
  ├─ 2. Фронт: маршрутизация по SNI/ALPN/типу пакета; неизвестное — закрыть без ответа.
  ├─ 3. Сервис: своя аутентификация (UUID, пароль, ключ туннеля + `inner`), PQ-шифрование.
  └─ 4. Выход: политика по пользователю и сервису, запрет приватных сетей.
```

Port-knocking не используется: он не добавляет защиты поверх SPA, а статичная последовательность
сама по себе отпечаток.

## SPA v2 (черновик формата)

Формат общий для `rayspa` и клиента Niko; спецификация и тестовые векторы будут лежать в `internal/spa/`.

**Ключи**
- У каждого устройства мастер-ключ `K_dev` (32 байта). Выдаётся при регистрации устройства по каналу с
  `X25519MLKEM768` или офлайн (QR).
- Эпоха `e = floor(t / E)`, длина эпохи `E` — случайный параметр установки (часы).
- Ключ эпохи: `K_e = HKDF-SHA256(K_dev, salt = node_id, info = "raycontrol-spa-v2" ‖ e)`.
- Компрометация ключа одной эпохи не раскрывает другие эпохи без `K_dev`.

**Порт**
- Слот `s = floor(t / S)`, длина `S` — случайный параметр установки (минуты).
- `port = base + HMAC-SHA256(K_port, s) mod range`; `K_port`, `base`, `range` — параметры ноды, клиент получает их
  при регистрации. `rayspa` держит открытыми слоты `s−1`, `s`, `s+1`.

**Пакет** — один UDP-датаграм, все байты неотличимы от случайных:

| Поле | Размер | Содержимое |
|---|---|---|
| nonce | 24 байта | случайные байты |
| ciphertext | остаток | XChaCha20-Poly1305(`K_e`, nonce, plaintext) |

plaintext: версия (1 байт), время (8 байт, unix-секунды), scope (список запрошенных сервисов),
запрошенный TTL, флаги, padding до случайной длины в диапазоне установки.

**Проверка в `rayspa`**
1. Пакет пришёл на текущий порт SPA; длина в диапазоне установки; ограничение частоты на источник — до криптографии.
2. Попытка расшифровки ключами активных устройств для эпох `e−1`, `e`, `e+1`
   (для десятков–сотен устройств это дёшево; при росте добавляется индекс).
3. `|now − time| ≤ 30 с`; nonce не встречался в окне.
4. Доступ = scope ∩ разрешённое устройству; адрес-источник (IPv4 или IPv6) добавляется в allow-наборы этих портов
   на TTL (по умолчанию 10 мин, продлевается новым пакетом).
5. Ответа нет никогда.

**Остаточные риски**
- Перехватчик на пути может отправить пойманный пакет со своего адреса раньше клиента (гонка). Он получает только
  сетевой доступ, без учётных данных сервиса.
- Связка «UDP-пакет на случайный порт → сразу TLS на 443» сама по себе поведенческий признак. Смягчение: клиент
  продлевает SPA независимо от моментов подключения и со случайной задержкой.
- Симметричная криптография с 256-битными ключами устойчива к квантовому перебору (уровень 128 бит).

## Исключения из полного закрытия

| Что | Почему | Ограничения |
|---|---|---|
| UDP 53 | DNS-туннели: пакеты приносят рекурсивные резолверы, SPA для них невозможна. | Отвечаются только свои делегированные зоны, остальное — `REFUSED`; лимиты на источник; размер ответа ограничен, чтобы не стать усилителем DDoS. |
| TCP 443 (или 80) на время ACME | Проверку Let's Encrypt выполняют чужие адреса. | Окно открывается только на время выпуска; фронт отдаёт ALPN `acme-tls/1` в `rayd`; если у DNS-провайдера есть API — DNS-01 без окна. |

## Постквант

| Где | Что включено |
|---|---|
| REALITY (Xray) | гибридный `X25519MLKEM768` (обязателен с Xray 26.9.8) + подпись `mldsa65Seed` |
| TLS у Hysteria2, naive, DoH, API, подписки | `CurvePreferences = [X25519MLKEM768]`, без отката на классические группы |
| DNS-туннели, olcRTC, OpenFlux | внутренняя ступень `inner`: VLESS с ML-KEM-768 |
| SPA | симметричные ключи 256 бит; выдача ключей — по PQ-каналу |
| Yggdrasil | проверить, возможен ли PQ; до проверки — без PQ, отмечено в профиле |

## Ротация

См. [01-architecture.md](01-architecture.md#ротация). Принципы:

- новое выпускается заранее, старое действует до конца окна перекрытия — клиент не теряет связь;
- клиент получает новое через подписанную подписку; ключи и порт SPA вычисляет сам;
- ротация SNI учитывает журналы Certificate Transparency (08, «Следствие 1»).

## Zero trust между компонентами

| Вызов | Канал | Аутентификация |
|---|---|---|
| `rayctl` → `rayd` | unix socket `0660 root:raycontrol` | `SO_PEERCRED` |
| Клиент → подписка и API | HTTPS за SPA, `X25519MLKEM768` | подписка — токен устройства; API — mTLS-сертификат устройства + роль |
| `rayd` → `rayspa` | unix socket | `SO_PEERCRED` (только UID `rayd`) |
| `niko-front` → бэкенд | unix-сокет бэкенда | права на сокет только у UID фронта; бэкенд проверяет `SO_PEERCRED` |
| `rayd` → Xray API | unix socket или loopback | только UID `rayd` (nftables `skuid`) |
| Движок белых списков → `inner` | unix socket | права только у UID движка; пользователь — по VLESS внутри туннеля |
| Процессы → секреты | `LoadCredential=` | каждый получает только свои |

Изоляция процессов: отдельные системные пользователи с фиксированными UID, `ProtectSystem=strict`,
`NoNewPrivileges`, минимальные `CapabilityBoundingSet`, `RestrictAddressFamilies`, `SystemCallFilter=@system-service`.
Исходящий трафик процессов-прокси: запрет 127.0.0.0/8, 10/8, 172.16/12, 192.168/16, 169.254/16, 100.64/10,
fc00::/7, fe80::/10 — в маршрутизации и в nftables по `skuid`.

## Аккаунты сторонних платформ

Режим выбирается при развёртывании сервиса (`platform_accts.mode`):

| Режим | Где аккаунт | Когда подходит |
|---|---|---|
| `node` | выделенный аккаунт в хранилище секретов ноды; сервис получает только свой | администратор обслуживает аккаунты сам; пользователю ничего не нужно |
| `client` | пользователь входит своим аккаунтом в клиенте (WebView, капча там же) | риск блокировки распределён по пользователям; на ноде нет чужих учётных данных |

В обоих режимах туннель внутри платформы шифруется своим ключом и ведёт в `inner`; платформа — недоверенная сторона.

## Логи

- Никаких секретов в логах, argv и окружении дочерних процессов.
- Журнал аудита — в базе, 90 дней. Access-логи выключены.

## Что проверяем тестами

- SPA v2: тестовые векторы с клиентом; повтор; просроченное время; чужой ключ; соседние эпохи и слоты; scope шире разрешённого; IPv6.
- Периметр: без SPA ни один порт, кроме UDP 53, не отвечает; окно ACME закрывается.
- Зондирование за SPA (SPEC §6.2): чужой SNI, naive без авторизации, мусор на UDP, чужая DNS-зона.
- PQ: соединение без `X25519MLKEM768` отклоняется у Hysteria2, naive, DoH, API.
- Изоляция: бэкенд не открывает сокет другого бэкенда; прокси не достаёт loopback и метаданные.
- Отпечатки: две установки с настройками по умолчанию не совпадают по портам, длинам пакетов и таймингам.
