# 04. Направления работ и этапы

Статус: **черновик для согласования**.

Работа разбита на направления (WS). Каждое направление закрывает свою часть находок аудита
([00-legacy-audit.md](00-legacy-audit.md)) и опирается на решения из
[01-architecture.md](01-architecture.md), [02-security-model.md](02-security-model.md) и
[03-protocols.md](03-protocols.md).

## Направления

### WS-0. Срочные исправления v0 (опционально)

Только если v0 сейчас где-то работает и до готовности новой версии его нельзя выключить.

- [ ] Hysteria: `auth.type: http` или параметризованный запрос вместо подстановки в SQL — L-01
- [ ] Xray: routing `geoip:private` → blackhole — L-02
- [ ] `del-user`: убрать `-q` при подсчёте или считать через `RETURNING` — L-10
- [ ] Включить `nftables.service`, проверка пустого `SSH_PORT` — L-13, L-14
- [ ] Лог `0600`, без паролей — L-03

### WS-1. Основа репозитория и сборка

- [ ] Go-модуль, структура каталогов из 01-architecture
- [ ] CI: `go vet`, `golangci-lint`, unit-тесты, `shellcheck` для `install/bootstrap.sh`
- [ ] Сборка релизов amd64/arm64, контрольные суммы и подпись релиза
- [ ] Манифест закреплённых версий движков (Xray, Hysteria, Caddy) с SHA-256
- [ ] Перенос `ray.sh`, `uninstall.sh` в `legacy/`, README с установкой из этого репозитория

Закрывает: L-52, L-57, L-58.

### WS-2. Ядро: модель данных и хранилище

- [ ] Схема SQLite и миграции (users, credentials, devices, instances, grants, traffic, api_tokens, audit_log, settings)
- [ ] Генерация секретов (crypto/rand), отдельные учётные данные на каждый инстанс
- [ ] Решение по шифрованию базы на диске
- [ ] Операции идемпотентны: повторный запуск ничего не теряет

Закрывает: L-12, L-20, L-50.

### WS-3. API и CLI

- [ ] protobuf-описание API, ConnectRPC-сервер в `rayd`
- [ ] Локальный API через unix socket, авторизация по `SO_PEERCRED`
- [ ] `rayctl`: users, devices, instances, links/QR, status, perimeter, backup
- [ ] Ссылки и подписки (URI, sing-box/Clash-форматы) по пользователю
- [ ] Журнал аудита
- [ ] Удалённый API: внутренний CA, mTLS, enrollment устройства по одноразовому токену, scopes

Закрывает: L-10, L-51; не допускает L-03 (секреты не в argv и логах).

### WS-4. Периметр

- [ ] `rayspa`: своя таблица `inet raycontrol` через netlink, без `flush ruleset`
- [ ] Knock: ограничения на каждый IP, устойчивость к ретрансмитам, счётчик ошибок, IPv4+IPv6
- [ ] SPA: формат пакета, X25519 + XChaCha20-Poly1305, окно времени, кэш nonce, scope, TTL
- [ ] Allow-наборы по инстансам, профили public/gated
- [ ] Port hopping для `hysteria@obfs` средствами `rayspa`
- [ ] Исходящий фильтр по `skuid` для процессов-прокси
- [ ] Аварийный доступ к SSH
- [ ] `rayknock`: CLI + Go-библиотека для будущего клиента
- [ ] Вариант на обсуждение: TOTP-последовательность портов стука

Закрывает: L-13, L-14, L-30, L-31, L-32, L-33, L-34, L-35.

### WS-5. Движки и протоколы

- [ ] Интерфейс `Engine` и общий тестовый набор для адаптеров
- [ ] Xray: VLESS + REALITY + Vision, self-steal, gRPC-синхронизация пользователей, статистика, routing
- [ ] Hysteria2: шаблонный юнит, инстансы `masq` и `obfs`, http-колбэк авторизации, Traffic Stats, ACL
- [ ] M5: XHTTP (вариант деплоя), PoC NaiveProxy, PoC TrustTunnel

Закрывает: L-01, L-02, L-21, L-40, L-41, L-43.

### WS-6. Сертификаты и сайт-приманка

- [ ] Caddy как сайт-приманка: шаблон сайта, loopback или unix socket для fallback REALITY и masquerade
- [ ] ACME: HTTP-01 по умолчанию; PoC TLS-ALPN-01 через fallback REALITY; DNS-01 опционально у любого провайдера
- [ ] Раздача сертификата движкам через `LoadCredential=` и перезагрузка после продления
- [ ] Проверка DNS: домен указывает на сервер (IPv4 и IPv6), без сторонних сервисов определения IP, если возможно

Закрывает: L-16, L-42.

### WS-7. Хост и изоляция

- [ ] Системные пользователи с фиксированными UID на каждый компонент и инстанс
- [ ] Systemd-юниты с hardening
- [ ] sysctl: `fq`, `bbr`, буферы UDP
- [ ] Решение по XanMod: опция или только sysctl на стоковом ядре; если опция — `signed-by` и https

Закрывает: L-04, L-07, L-53, L-55.

### WS-8. Эксплуатация

- [ ] `install/bootstrap.sh` + `rayctl install`: проверка ОС и архитектуры, журнал установленного
- [ ] `rayctl update`: движки и сам raycontrol, проверка сумм, откат при неудаче
- [ ] `rayctl backup` / `restore`: зашифрованный архив, проверка на чистом хосте
- [ ] `rayctl uninstall` по журналу установки: чужие пакеты и данные не трогаются
- [ ] Статус и мониторинг: состояние сервисов, соединения по `sport`, трафик из API движков
- [ ] Логи: journald, сроки хранения, access-логи выключены по умолчанию

Закрывает: L-05, L-06, L-11, L-15, L-17, L-18, L-19, L-54, L-56.

### WS-11. Агрегация: модель, манифесты, плагины, ray-core

- [ ] Единая модель трафика (вход → носитель → маскировка → сессия → аутентификация → маршрут → выход) в API и базе
- [ ] Манифест движка и его проверка при `rayctl service add`
- [ ] Аллокатор ресурсов: порты, UID, TUN и подсети, имена наборов nftables, юниты, каталоги, домены
- [ ] Контракт внешнего плагина-адаптера (gRPC через unix socket), SDK и пример плагина
- [ ] Контракт `ray-core`: unix-сокеты на каждый сервис, аутентификация пользователя внутри туннеля, учёт, политика выхода
- [ ] `ray-core` на Xray или sing-box (PoC и выбор), затем место под своё ядро
- [ ] Профили подключения: сборка из сервиса, учётных данных и параметров клиента; подписанная подписка

### WS-12. Транспорты белых списков

По [05-transports-research.md](05-transports-research.md). Каждый транспорт проходит PoC: сборка, адаптер,
изоляция, проверка в целевой сети, вывод «включаем / наблюдаем / отказываемся».

- [ ] DNS-класс: MasterDnsVPN, dnstt, Slipstream — выбор основного; NS-делегирование в аллокаторе доменов
- [ ] rendezvous: olcRTC (Jitsi datachannel), OpenFlux (выход L4, шифрование обязательно), S3 Bypass (форк s3network)
- [ ] relayed: qWDTT (L3: TUN, подсеть, NAT через `rayspa`)
- [ ] CSQTT: наблюдать за форками с подходящей лицензией
- [ ] Для движков без пользователей — выход только через `ray-core`

### WS-13. Учётные данные третьих сторон

- [ ] `vault`: хранение, выдача только своему сервису, ротация, статус проверки
- [ ] Типы: аккаунт VK (хэши звонков), аккаунты Телемоста и WB Stream, аккаунты сервисов документов, S3-ключи
- [ ] Проверка работоспособности и уведомление о блокировке аккаунта
- [ ] Лимиты расходов для платных платформ (S3)

### WS-9. Тестирование

- [ ] Unit-тесты: store, render, SPA-криптография, authz
- [ ] Правила nftables в network namespace: сценарии knock, SPA, профили, исходящий фильтр
- [ ] Интеграция в VM: Debian 12/13, Ubuntu 24.04 × amd64/arm64; установка → подключение реальными клиентами
      (Xray, Hysteria, sing-box) → удаление
- [ ] Проверка конфигов движков (`xray run -test` и аналоги) в CI
- [ ] Проверки безопасности: прокси не достаёт loopback и метаданные; чужой UID не достаёт API Xray и колбэк

### WS-10. Миграция с v0

- [ ] Импорт из PostgreSQL v0: VLESS UUID и пароли Hysteria с именами по умолчанию
- [ ] Trojan не переносится: пользователей предупреждаем
- [ ] Удаление следов v0: юниты, `/etc/ray-aio`, база `ray_aio_db`, правила nftables

## Этапы

| Этап | Содержание | Направления | Результат |
|---|---|---|---|
| **M0 — База** | Ответы на вопросы M0; каркас репозитория и CI; хранилище и миграции; единая модель, манифест движка, аллокатор, контракт плагина; `rayd` + `rayctl` через unix socket с CRUD пользователей и сервисов без движков. | WS-1, WS-2, WS-3 (локальный API), WS-11 (модель и контракты) | Скелет ноды, на который навешиваются движки. |
| **M1 — Основные протоколы** | Caddy + ACME; Xray REALITY self-steal; Hysteria2 `masq` и `obfs`; ссылки и подписки; юниты с hardening; исходящий фильтр. | WS-5, WS-6, WS-7 | Рабочий сервер для сторонних клиентов. |
| **M2 — Периметр** | `rayspa`, knock + SPA, профили, SSH за гейтом, аварийный доступ, `rayknock`. | WS-4, WS-9 | Многоуровневая защита. |
| **M3 — API для клиента** | Удалённый API, внутренний CA, enrollment, scopes, аудит. | WS-3 | Основа для будущего клиента. |
| **M4 — Эксплуатация** | Установщик, обновление, бэкапы, удаление, мониторинг, миграция с v0. | WS-8, WS-10 | Готово к замене v0. |
| **M5 — Новые direct-протоколы и ray-core** | XHTTP, PoC Naive и TrustTunnel; `ray-core` на Xray или sing-box. | WS-5, WS-11 | Расширенный direct-набор, готовая внутренняя ступень. |
| **M6 — Белые списки** | `vault`; PoC и адаптеры DNS-класса, olcRTC, OpenFlux, qWDTT, S3 Bypass. | WS-12, WS-13 | Работа при блокировке IP и в режиме белых списков. |

WS-9 идёт сквозным потоком: тесты пишутся вместе с кодом каждого этапа.
