## 1. `udp_mtu` в сводке — сделано (raycontrol v0.8.0, R4-25)

- **В отчёте** — поле верхнего уровня, как вы предложили:

  ```json
  {"v": 1, "net": "cellular", "udp_mtu": "1350-1472", "obs": [...]}
  ```

  Корзины: `<1200`, `1200-1350`, `1350-1472`, `1472+`. Поле необязательное. Другое значение и поле внутри `obs[]` —
  `400`.
- **В подсказке** — `hints.udp_mtu`: корзина, на которую пришлись не меньше 60 % отчётов с полем, при k ≥ 10 таких
  отчётов. `<1200` — QUIC (Hysteria2, naive по QUIC, DoH3) в этой AS скорее не пойдёт.
- **У администратора** `rayctl summary` показывает распределение по сети.

## 2. Как клиенту понять, что нода поле знает

Отчёт по-прежнему строгий. Нода v0.7 и раньше на отчёт с `udp_mtu` ответит `400`, а `400` у вас закрывает сутки:
отчёт пропал бы. Поэтому подписка теперь перечисляет необязательные поля отчёта:

```json
"probe": {"v": 1, "udp": true, "report": ["udp_mtu"], "tunnel": "probe.raycontrol.invalid", "tunnel_svc": [...]}
```

Шлите `udp_mtu` только если оно есть в `probe.report`. Нет `report` — значит, нода старая: отчёт без поля. Так же
будут объявляться следующие необязательные поля.

Спецификации: `probe-v1.md` §6.1–6.2, `subscription-v1.md` §3.
