## 1. Совместимость

- **Подписка v1 и `/sub/v1` не меняются.** Добавлены только необязательные вещи, как договорились в §6
  `niko-r3-reply.md`:
  - поле payload `probe`;
  - вид профиля Yggdrasil и параметр ссылки `niko-ygg`.

  Неизвестное клиент по-прежнему игнорирует.
- **api-v1 не менялся.**
- **`rayd naive` изменился.** Он больше не слушает TCP сам: сокеты передаёт фронт niko-server. Появился флаг
  `-probe`. Это важно для твоего `raycontrol-interop.yml` (§6).

## 2. Фронт на 443 (`niko-mux-note.md`)

- **TCP 443 (tcpmux).** Маршрут по SNI:
  - REALITY → Xray (PROXY v2);
  - DoH и naive → `rayd`;
  - Yggdrasil → бэкенд niko-server;
  - неизвестное имя → REALITY → сайт-приманка.
- **UDP 443 (udpmux).**
  - `hy2-masq` — по имени в QUIC Initial.
  - **`hy2-obfs` теперь тоже на 443**: фронт узнаёт его по salamander. Порт в ссылке — 443, ротация портов ведёт туда
    же.
  - DoH3 и naive-quic — по своим именам. naive-quic — это `naive+quic://` с теми же параметрами; DoH3 — тот же URL по
    HTTP/3.
- **`services[].port_key` есть теперь и у DoH и naive**, потому что у них появился UDP 443.
- **Фейки перед QUIC.** Мусор и Initial с чужим именем отбрасываются и поток не закрепляют, так что их можно слать.
  **Нельзя использовать в фейках имена самой ноды**: такой пакет закрепит поток за её бэкендом.
- **Разбитый ClientHello фронт собирает сам.**
  - QUIC: из нескольких Initial, до 16 пакетов за 3 с.
  - TCP: из нескольких TLS-записей, до 64 КиБ. Если ClientHello не пришёл за 5 с, соединение закрывается молча.
- **Сервер Hysteria2 теперь sing-quic в niko-server**, не Xray. Условия Xray из твоего §13 п. 5 (`congestion`,
  `brutalUp`) к нему не относятся (§5).

## 3. Yggdrasil — новый вид профиля (`niko-ygg-note.md`)

```
vless://<uuid>@[<адрес ноды в Yggdrasil>]:<порт выхода>?type=raw&encryption=mlkem768x25519plus.native.0rtt.<ключ>
  &niko-node=<node_id>&niko-svc=<id>&niko-ygg=<пир>%3B<seed>#<имя>
```

- **`niko-ygg` = `<пир>;<seed>`.**
  - Пир — `tls://<имя>:443?key=<ключ ноды, hex>&sni=<имя>`. Единственный пир профиля: подключение только прямое (P-14).
  - `<seed>` — закрытый ключ узла клиента: seed ed25519, 64 hex-символа.
- **Конфиг ядра.**
  - endpoint `yggdrasil`: `private_key` = seed (`parsePrivateKey` форка принимает seed 32 байта), `peers` = [пир],
    `tls_fingerprint` — `chrome`;
  - исходящий `vless` на `[адрес]:порт` с `detour` на endpoint, `encryption` — как у DNS-туннелей.
- **Что делает нода.**
  - TLS 1.3 только с `X25519MLKEM768` — uTLS Chrome 133 его предлагает. Сертификат — сайта ноды, Yggdrasil его не
    проверяет.
  - Линк пускается, только если ключ из рукопожатия есть у пользователей.
  - Из mesh открыт только порт выхода, он ведёт в `inner`; на другие порты — сброс, UDP не принимается.
  - Всё, что не линк, получает пустой `404`.
- **Ротация.** Ключ клиента выводится на сервере из UUID `inner`. Поэтому в `next` приходит новая пара UUID + seed;
  старая работает ещё 2 дня после `from`. Сам клиент ничего не выводит: берёт seed из ссылки.
- **SPA.** TCP 443, `svc` — ID сервиса Yggdrasil.
- **Проверка.** На сервере проверено рукопожатие ключом из подписки на настоящем niko-server. **Клиентом Niko не
  проверено** — это твоя часть (§6).

## 4. Замер канала (`niko-probe-note.md`, формат — `docs/spec/probe-v1.md`)

**Напрямую.**
- **Где.** Эндпоинт подписки: тот же `host:sub.port`, тот же пин `sub.pin`, та же авторизация (`X-Raycontrol-Device`
  и `Authorization: RC1 <minute>.<mac>`). Неавторизованным — `404`.
- **Признак.** В payload подписки:

  ```json
  "probe": {"v": 1, "udp": true, "tunnel": "probe.raycontrol.invalid", "tunnel_svc": [3, 4, 5]}
  ```

- **Запросы.**

  | Запрос | Ответ |
  |---|---|
  | `GET /probe/v1/down?bytes=N` (N до 256 МиБ) | `N` байт, затем trailer `Probe-Result: bytes=…; ms=…; rtt_us=…; rttvar_us=…; min_rtt_us=…; retrans=…; delivery_bps=…; cwnd=…; pmtu=…` — `TCP_INFO` сокета сервера |
  | `POST /probe/v1/up?bytes=N` + тело | JSON `{"bytes","ms","tcp":{…}}`; `ms` — от первого до последнего байта на сервере |
  | `POST /probe/v1/udp` | `{"token","port","seconds":30,"max_rate":1000,"budget"}` |
  | `GET /probe/v1/udp?token=…` | закрывает сессию; счёт сервера `{"received","echoed","dropped","bytes"}` |
  | `GET /probe/v1/link` | вид сервера на соединения адреса запроса (ниже) |

- **Эхо UDP**, как irtt.
  - Датаграммы — на `<host>:<port>` (тот же номер, что `sub.port`; SPA открывает его вместе с TCP).
  - Формат: `token(16) | seq(4, BE) | время клиента(8, BE, ns) | время сервера(8) | заполнение`, от 36 байт.
  - Сервер возвращает ту же датаграмму той же длины, вписав время приёма в байты 28–35.
  - Отвечает только первому адресу сессии и не чаще `max_rate` в секунду.
  - Длину выбирает клиент, ею же проверяется MTU: фрагменты нода отбрасывает.
  - Потери вверх = отправлено − `received`; потери вниз = `echoed` − получено.
- **`link`.** Только суммы, потому что за одним адресом при CGNAT бывают чужие соединения.
  - TCP 443: `connections`, `rtt_us` {min, median, max}, `min_rtt_us`, `retrans`, `segs_out`, `retrans_rate`,
    `delivery_bps` {…}.
  - `hysteria2` — по ID сервиса: `connections`, `rtt_us`, `min_rtt_us`, `packets_sent`, `packets_lost`, `loss_rate` и
    `brutal` {`connections`, `rate_bps`, `ack_rate` {min, median, max}}.
  - Только напрямую: через туннель — `409`. Не чаще раза в 5 с, иначе `429`.
- **Ограничения.**
  - Один замер на устройство одновременно (TCP-запрос или сессия UDP); второй — `429`.
  - До 30 с на замер.
  - 1 ГиБ на устройство за сутки UTC в обе стороны; сверх — `429` с `Retry-After`.
  - `link` в объём не входит.

**Через туннель профиля.**
- Внутри туннеля сервиса из `probe.tunnel_svc` обратись к `probe.raycontrol.invalid` на любом порту. Запросы, TLS с
  пином, авторизация и ограничения — те же, что напрямую.
- Выходы:

  | Выход | TCP | UDP |
  |---|---|---|
  | Xray: `inner` (DNS-туннели, Yggdrasil) и REALITY | да | да, через VLESS UDP |
  | `rayd naive` | да | нет |
  | Hysteria2 | да | да; ответы приходят от имени |

- **UDP через REALITY шли не на 443**: Vision не пропускает UDP 443. Бери порт из ответа сессии.

**Образец клиента.** `internal/probe/client.go` в raycontrol (`Down`, `Up`, `Echo`, `Link`) и
`rayctl probe -channel <бандл>`. Тест установки гоняет его через настоящий SPA на пяти системах.

## 5. Brutal (твой §13 п. 5)

- **Потолок отдачи.** `rayctl service set <hy2-masq|hy2-obfs> up_mbps=N` — потолок на одно соединение. Сервер шлёт
  клиенту со скоростью min(N, твой `Hysteria-CC-RX`). Без темпа клиента — BBR. По умолчанию потолка нет: темп
  клиента берётся как есть.
- **Потолок приёма.** `down_mbps=N` ограничивает отдачу клиента; `0` снимает потолок.
- **Подбор темпа.** Объявляй темп приёма по замеру (`down` + эхо UDP). Затем следи за `link.hysteria2.<svc>.brutal.ack_rate`:
  если он держится ниже ~0,9, заявленный темп выше того, что пропускает путь, — снижай.

   - Темп Brutal по замеру и `ack_rate` (§5).
   - Фейки перед QUIC без имён ноды (§2).
2. **CI совместимости.**
   - `raycontrol-interop.yml` → коммит `5e3c5ec`. Перед `rayd naive` подними фронт niko-server (порядок — в
     `niko-mux-note.md` §3, как в тесте `TestRealitySelfStealWithXray`). Флаги `rayd naive`: `-socket` (fd),
     `-quic-socket` (packet), `-front-uid`; `-probe 127.0.0.1:<порт подписки>` — для замера через naive.
   - `niko-server-interop.yml` → `v0.6.0`. Добавь:
     - Hysteria2 обоих видов через udpmux своим ядром;
     - Yggdrasil через tcpmux своим ядром (`with_yggdrasil`);
     - замер напрямую и через туннель (нужен `rayd` с эндпоинтом подписки — проще в `raycontrol-interop.yml`).
3. **Когда будешь готов — п. 4 §13** (сводка от клиентов): предложи формат и что именно клиент готов отдавать с
   согласия пользователя. Рамку сервера смотри в `niko-probe-note.md` §5: явное согласие; грубые категории без
   адресов, идентификаторов устройств и точного времени; k-анонимность на ноде; короткое хранение; защита от
   отравления; вероятно, `POST /probe/v1/report`. После твоего предложения сервер определит хранение, агрегацию и
   обратную подсказку. Остальной §13 закрыт.
4. **Подсказка о порядке профилей в подписке** (п. 3): скажи, на каких сигналах ты хочешь её получать. У сервера
   сейчас есть только `link`, а этого мало для совета.
