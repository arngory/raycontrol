# raycontrol → Niko: новое имя naive в `next` (R4-42, raycontrol v0.29.0)

Заметка для сессии клиента. С v0.29.0 нода меняет имя сервера naive (`sni`) эпохами и по команде оператора. Контракт
не меняется: новое имя приходит в уже существующем `profiles[].next` — та же строка `naive+https://` с другим `sni`
([subscription-v1](../spec/subscription-v1.md) §3, §4; разбор — [naive-sni-rotation.md](../research/naive-sni-rotation.md)).
Клиенту ничего делать не нужно; ниже — что нода обещает и как получить такой `next` на стенде.

## 1. Что обещает нода

- **`next` naive.** Та же строка, другое `sni`; если следующий пароль уже опубликован и его смена не раньше смены
  имени — с ним. Адрес, порт, `niko-pin`, `uot`, `icmp`, `niko-ack`, имя профиля — те же. В одном `next` — ближайшая
  смена (имени или пароля), как у REALITY.
- **Пины.** Ключ сайта при смене имени не меняется: `niko-pin` в `link` и в `next` одинаковый.
- **Новое имя** фронт обслуживает (TCP и UDP 443) с предыдущей смены, то есть задолго до публикации: `next` можно
  пробовать за 120 с до `from` и раньше.
- **Прежнее имя** фронт обслуживает до следующей смены имени (90 дней по умолчанию), и после `rotate -now` тоже:
  откат на `link` работает всю эпоху.
- **Две смены подряд** (`-now` дважды, `-now` вскоре после плановой) имени, бывшего текущим две смены назад, больше
  не снимают: каждое прежнее имя фронт обслуживает до смены не раньше чем через период (90 дней) после той, что его
  оставила, но не больше трёх прежних имён. Снятым может оказаться только самое старое сверх трёх — или имя, оставленное
  больше периода назад; устройство, у которого есть только оно, проходит, лишь забрав подписку. Имя, которого нет в
  маршрутах, по TCP попадает в REALITY и получает ответ сайта, по UDP фронт молчит.
- **Когда.** По расписанию — только под wildcard-сертификатом ноды (DNS-01) или с `rotate_sni=on`; иначе — по
  команде оператора (имя заблокировали). Публикация за `-cred-lead` (3 дня).

## 2. Как получить опубликованный `next` на стенде

Нода под `rayd serve -supervise`, как в interop (`test/supervise/run.sh` делает то же):

```bash
rayd serve -supervise -xray … -niko-server … -acme-directory "" -cred-lead 5m   # next за 5 минут до смены, не за 3 дня
rayctl service add reality reality
rayctl service add naive naive
rayctl service cert site -chain chain.pem -key key.pem    # сертификат оператора; wildcard *.<домен> покрывает новые имена
rayctl user add alice -services reality,naive
rayctl service rotate naive        # next с новым sni в подписке за секунды, from = сейчас + 5 мин
rayctl service rotate naive -now   # переход сразу: link — новое имя, старое ещё обслуживается
```

`-cred-lead` — обычный флаг `rayd serve` (он же срок публикации UUID и ключей REALITY); отдельного скрытого
переключателя нет. Сертификат должен покрывать новое имя: при сертификате со списком имён без ACME смена ждёт
сертификат и через сутки (`-reality-prepare`) отменяется. Что опубликовано, видно в `rayctl status` (строка
`naive naive`) и в `rayctl user export alice` (строка `# naive from …`).

## 3. Что ещё изменилось рядом

- REALITY по расписанию больше не меняет имя без wildcard-сертификата; ключи и shortId — меняет. По команде — и имя.
- Второй REALITY на одном сайте получает своё имя; раньше два REALITY с одним именем роняли фронт.
