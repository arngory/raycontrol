## 1. `quic://` в `niko-ygg-via` — только IP (сделано, v0.5.1)

- `rayctl service set ygg peers=…` не принимает `quic://` с именем. Сообщение об ошибке объясняет почему.
- Пир `quic://` с именем, заданный раньше, в ссылку не попадает, хотя нода с ним по-прежнему пирится.
- `tls`, `tcp`, `ws`, `wss` — с именем, как раньше: их клиент резолвит своим DNS через `LinkDialer`.

## 2. Сводка и подсказки — на ноде есть (v0.5.0)

- `POST /probe/v1/report` работает по `probe-v1.md` §6. Включайте отправку в клиенте с согласия пользователя.
- Ваша логика на ответы — та же, что у нас: `404` значит «нода не принимает, не повторять до следующих суток»,
  `429` значит «эта сеть уже сегодня».
- `hints` приходит в подписке для AS адреса запроса, при k ≥ 10 (`subscription-v1.md` §3, `probe-v1.md` §6.2).
  В §15 не сказано, читает ли клиент `hints`. Если ещё нет — это следующий шаг, порядок применения по вашему §14.4.

## 3. Тесты: что даёт сервер для вашего CI

Всё ниже проверено у нас на настоящих бинарниках. Шаблоны — в тестах raycontrol.

1. **`own` (niko-server v0.7.0).**
   - Напрямую: `stats_socket` бэкенда Hysteria2, строка `<адрес> <имя>`. Имя — `name` пользователя в
     `users_file`, в raycontrol это `u<ID>`. В ответе `own` — сессии этого пользователя.
     Шаблон — `probeThroughHysteria` в `internal/xrayapi/xray_test.go`.
   - Через `rayd` (`GET /probe/v1/link`): клиент должен прийти не с loopback, иначе `409`. Нужен отдельный сетевой
     namespace или контейнер. Так делает наш тест установки.
2. **Замер через туннель.**
   - Xray (`inner`, REALITY): `internal/xrayapi/probe_test.go`.
   - Hysteria2 (niko-server `options.probe`): `probeThroughHysteria` там же.
   - Имя `probe.raycontrol.invalid`, пин и `RC1` — как напрямую.
3. **Отчёт и подсказка.** Подсказка нужна AS, а в CI адреса частные. Локальные базы AS в v0.5.1 отвечают за любой
   адрес, который в них есть. Поэтому:
   1. `go run ./test/install/asndb -o asn.mmdb 172.16.0.0/12` (из raycontrol; сеть — ваша тестовая);
   2. на ноде — `rayctl summary db asn.mmdb` и `rayctl summary on`;
   3. 10 устройств по одному отчёту — `204`; повтор того же устройства — `429`;
   4. следующая подписка несёт `hints`: `order` — сервисы с 10 наблюдениями.

   Эталонный клиент — `rayctl probe -report '{…}' @bundle`: он отправляет отчёт и печатает `hints` своей сети.
   Весь путь гоняет наш тест установки (`test/install/run.sh`).

## 4. Готовность клиента к серверу — взгляд сервера

**Проверено вашим CI против настоящих компонентов сервера:**
- SPA v2, подписка v1 (обе подписи), `rcdev1` и `rcinv1`, удалённый API (регистрация, вызовы администратора, смена
  ключа);
- DNS-туннели → `inner`;
- Hysteria2 `hy2-masq` и `hy2-obfs` через udpmux;
- naive h2 и QUIC через фронт → `rayd naive`;
- Yggdrasil через tcpmux;
- замер напрямую: `down` с trailer, `up`, эхо, `link` → `409` с loopback;
- ядро на `arngory/yggdrasil-go` (Go 1.26), живой mesh с публичными пирами.

**Сделано в клиенте, но против сервера ещё не проверено:**
- `own` — нужен niko-server v0.7.0 в `niko-server-interop.yml`;
- замер через туннели (блок G) — в CI его нет;
- `niko-ygg-via` против нашей ноды с включёнными пирами — живой mesh был, но не с нашей нодой;
- отправка сводки — эндпоинт есть с v0.5.0;
- чтение `hints` — не упомянуто.

**Не проверено ни нами, ни вами:**
- настоящая сеть: нода на VPS, клиент на мобильной сети, DPI;
- переход REALITY на новые ключи с реальным клиентом;
- долгая работа без перезапусков.

**Итог.**
- По протоколам и форматам клиент совместим с сервером, и это подтверждено CI с обеих сторон.
- Отставание по закреплениям — на два релиза сервера.
- Главный риск — не формат, а отсутствие проверки в настоящей сети.

**Предлагаемый порядок:**
1. поднять закрепления (raycontrol v0.5.x, niko-server v0.7.0);
2. добавить в interop `own`, замер через туннель, отчёт и `hints` (§3 выше);
3. проверка на VPS по `docs/10-quickstart-debian13.md` с настоящим клиентом.
