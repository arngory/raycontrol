# raycontrol → Niko: relay в `GetUpdateStatus` (relay-update-remote-v1 §8)

Заметка для сессии клиента Niko, для админки. С raycontrol v0.28.0 нода, обновившись, называет свою версию своим relay,
и relay, на которых root это разрешил (`rayctl update remote on` там), обновляются сами, по одному. Ответ
`GetUpdateStatus` несёт об этом новое поле `relays`. Формат —
[relay-update-remote-v1.md](../spec/relay-update-remote-v1.md) §8, согласован с клиентом 2026-11-14: поля как есть,
времена в секундах, `seen_at` — любая связь, `reason` — код, `error` — текст. В node.v1 только добавления: Niko 1.54.0
(админка для v0.27.0) с нодой v0.28.0 работает как раньше и строк relay не показывает.

## 1. Поля

```proto
message GetUpdateStatusResponse {
  // ... 1-9 as before
  repeated RelayUpdateStatus relays = 10;
}

message RelayUpdateStatus {
  string name = 1;
  string version = 2;    // what the relay last said it runs; "" never said
  string state = 3;      // §2 below
  string target = 4;     // the version offered; "" none
  string update_id = 5;  // the node's update it follows (UpdateStatus.id)
  string reason = 6;     // a code (§3 below); "" none
  string error = 7;      // short text for a person, redacted, at most 200 bytes
  int64 changed_at = 8;  // unix seconds: when state became what it is
  int64 seen_at = 9;     // unix seconds: when the node last heard the relay at all; 0 never
  bool remote = 10;      // root on the relay takes the node's word (rayctl update remote on)
}
```

- **Список** — все relay ноды (как `rayctl relay list`), по имени. Нет relay — пустой список. Нет поля — нода до
  v0.28.0: строки relay не показывать.
- **Времена** — unix-секунды по часам ноды, как `UpdateStatus.ended_at`; часы relay не участвуют.
  - `changed_at` — когда `state` стал тем, что есть. У `unknown` — 0. У `offered` — когда нода дала relay очередь.
    У `waiting` — когда кончилось обновление ноды, за которым relay ждёт (одно время у всех ждущих). У `failed` с
    `no_word` — когда нода перестала ждать (§2).
  - `seen_at` — когда нода слышала relay вообще: открытый поток фида (тогда — время ответа) или любой его доклад,
    не только об обновлении. 0 — никогда. По нему — «давно не на связи», отдельно от `state`.
- `version` и `remote` — что relay сказал о себе последним. `remote: false` — root на relay не разрешил.
- `target` и `update_id` — версия, которую нода назвала, и обновление ноды, за которым relay идёт. Если `update_id`
  равен `status.id`, это последнее обновление самой ноды. С какой версии шёл relay, в сообщении нет: его прежняя
  версия — `version` до итога.
- `reason` — машинный код, его клиент переводит сам (§3). `error` — короткий текст на английском, без адресов и
  ключей: relay пропустил его через `redact`, нода — ещё раз, затем только печатные символы и не больше 200 байт.
- **Незнакомое показывать как есть:** код `reason`, которого нет в §3 (relay бывает новее ноды), и `state`, которого
  нет в §2.

## 2. `state`: как нода сводит его сейчас

Нода сводит доклад relay, своё предложение и место relay в очереди в одно `state`
(`relayStatus`, `internal/api/relayupdate.go`). Проверки — по порядку, первая подошедшая:

| # | Когда | `state` | `target`, `update_id` |
|---|---|---|---|
| 1 | нода сейчас ничего не называет, relay ни разу не докладывал | `unknown` | пусто |
| 2 | нода ничего не называет, relay ещё обновляется по прошлому предложению | `requested` или `running` | его прошлые |
| 3 | нода ничего не называет | `current` | пусто |
| 4 | relay доложил об этом предложении (не `idle`) | как доложил: `requested`, `running`, `done`, `rolled_back`, `failed` | предложения |
| 5 | у relay очередь: предложение в его потоке, доклада о нём ещё нет | `offered` | предложения |
| 6 | relay ни разу не докладывал (старше v0.28.0, без `rayd relay`, не подключался) | `unknown` | пусто |
| 7 | relay на `target` или новее | `current` | предложения |
| 8 | relay ещё обновляется по прошлому предложению | `requested` или `running` | его прошлые |
| 9 | relay младше `target`, root на нём не разрешил | `off` | предложения |
| 10 | его очередь не пришла: перед ним не все прошли, или занят другой | `waiting` | предложения |
| 11 | очередь прошла relay без слова о предложении | `failed`, `reason: no_word` | предложения |

- **«Ничего не называет»** (строки 1–3): у ноды ждёт или идёт своё обновление; или удавшегося обновления ещё не
  было; или последнее удавшееся было `rayctl update -no-relays`; или нода на другой версии, чем то обновление
  поставило (откат или установка руками). После обновления, которое откатилось или не удалось, нода называет прошлое
  удавшееся, пока на нём.
- **`no_word` бывает двух видов.** В строках 2, 4 и 8: relay сказал `requested` или `running` и за час не сказал
  итога — нода отдаёт `failed`, `no_word`, `changed_at` — когда он впервые сказал одно из них по этому `update_id`,
  плюс час (что он говорит между — `requested` и `running` по очереди, `remote` — час не сдвигает). В строке 11:
  очередь relay вышла (40 минут с тех пор, как нода её дала) или его `rayd relay` 40 минут не на связи;
  `changed_at` — когда это случилось. Текст в `error` у видов разный.
- **Что кончается.** `offered` — не дольше 40 минут, затем доклад или `failed` (`no_word`). `waiting` — пока не
  пройдут relay перед ним и тот, кто занят; каждый держит очередь не дольше 40 минут без потока до неё и 40 минут в
  ней. `requested`, `running` — итогом или через час `failed` (`no_word`). Обычное обновление relay — минуты.
- **Что может вернуться.** Relay с `failed` (`no_word`) снова бывает `offered` или `requested`: он вернулся до своей
  очереди или взял предложение позже.
- **Отказ relay** (свою причину он докладывает итогом по `update_id`): `failed`, `reason` — `version` или `busy`.
  Это итог, очередь идёт дальше.

## 3. Коды `reason`

| Код | Что значит | До изменений |
|---|---|---|
| `policy` | root на relay: `remote` выключен к моменту запуска | да |
| `stale` | root на relay: запрос старше часа | да |
| `version` | root: не новее, ниже v0.26.0 или версия не удержалась на relay раньше (`held`); `rayd relay`: предложение не взято (`held`, сборка не релиз, `done` под другим `id`) | да |
| `busy` | root: замок обновления не взят за 3 минуты; `rayd relay`: предложение отложено (6 часов после сбоя без изменений, не больше запроса за 10 минут и шести за сутки) | да |
| `unfinished` | прошлое обновление relay руками не кончилось: нужен root на relay | да |
| `bundle` | пакет relay пропал или не читается | да |
| `ssh` | снимок периметра не пустит SSH на порт sshd relay | да |
| `download` | ни GitHub, ни зеркала не отдали файлы | да |
| `signature` | подпись не та или подписана другая версия | да |
| `place` | первый бинарник не встал (диск) | да |
| `install` | установка relay не прошла; откат | нет |
| `check` | проверка после установки не прошла; откат | нет |
| `interrupted` | обновление оборвалось (убито, таймаут, выключение): откат после; до первого изменения — без отката | нет; да, если до первого изменения |
| `open` | прежний relay не вернулся: хост открыт и не пересылает, нужен root | нет |
| `not_taken` | `rayd relay`: root не взял запрос за час | да |
| `no_word` | нода: relay замолчал (§2) | — |

«До изменений» — relay остался как был; `rolled_back` — прежняя версия relay вернулась и проверена. Поле
`unfinished` из доклада relay нода телефону не отдаёт: что нужен root, видно по коду (`unfinished`, `open`).

## 4. Что нужно от клиента

- **Строка relay:** имя, версия, состояние, время `changed_at`, причина (`reason` по §3, `error` — как есть). При
  старом `seen_at` — пометка «давно не на связи».
- **Подсказки** (команды — на хосте relay, от root): `off` — `rayctl update remote on`; `unknown` — relay старше
  v0.28.0 или без точки замера: `rayctl update` там руками, затем `rayctl update remote on`.
- **Опрос.** После `StartUpdate` опрашивать `GetUpdateStatus`, как сейчас, пока свой `status` не итог **или** хоть
  один relay в `waiting`, `offered`, `requested`, `running`. Все четыре кончаются (§2), но с несколькими relay
  дольше нынешних 20 минут опроса Niko: каждый relay — минуты, а молчащий держит очередь до 40 минут в ней и
  пропавший до неё — ещё до 40. Разумно после итога ноды опрашивать реже или при открытии экрана.
- **Кнопки для relay нет.** Нода называет relay только свою версию: обновить relay отдельно, на другую версию или
  придержать его с телефона нельзя (решение владельца, spec §11 п. 2). Придержать — `rayctl update remote off` на
  relay.
- **`status` показывает и ручное обновление ноды:** `kind: "local"`, `by: "rayctl on the node"` (клиенту сообщено
  2026-11-14, spec §11 п. 1). `kind: "local"` был и раньше — у отката руками, `by: "root (rayctl update -rollback)"`;
  комментарий к `UpdateStatus.kind` в `node.proto` называет только `remote` и `auto`.

## 5. Что проверено

- **Модульные тесты ноды** (`internal/api`, `relayupdate_test.go`, `relayturn_test.go`): сведение `state` по §2,
  очередь по именам с часами теста, `no_word` обоих видов, перезапуск ноды посреди очереди, доклады relay в границах
  и вне их. `rayctl update status` со строками relay — `cmd/rayctl/update_status_test.go`.
- **Interop против `rayd serve -supervise`** может видеть только начало: у такой ноды нет обновлений по запросу, и
  она ничего не называет. Relay, добавленный `rayctl relay add` и ни разу не подключённый, — `unknown`; с запущенным
  `rayd relay` v0.28.0 — `current` и `remote: false`.
- **Проверено:** модульными тестами и в CI в контейнерах (spec §12.2): обновление relay по слову выхода до конца,
  откаты, прерывания и чужая подпись доходят до `GetUpdateStatus.relays`. **Не проверено** на настоящем хосте relay
  (§12.3).
